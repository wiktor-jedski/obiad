# Task 3

## Description

Add one `themealdb` recipe Adapter to the offline production-data authoring
workflow in [`data/src/obiad_data/recipe.py`](../../../data/src/obiad_data/recipe.py).
The Adapter must use the existing `scrape_recipe` seam and return one
`ScrapedRecipe`. It must not create a second acquisition interface.

This task implements the recipe acquisition part of
[ARCH-013](../../architecture/architecture.md#arch-013--food-catalog-data). It
does not add a production Meal or change the application catalog, backend,
frontend, or OpenAPI interface.

Use only the official TheMealDB JSON API. Do not scrape TheMealDB website pages.
The task is limited to the documented development key and one explicit lookup:

`https://www.themealdb.com/api/json/v1/1/lookup.php?i={idMeal}`

The Adapter must fetch only one agent- or developer-selected Meal ID at a time.
It must not search, filter, list, request random Meals, enumerate the database,
follow `strSource`, download artwork, or write a Meal automatically. Development
key access does not approve production use or publication.

Register the Adapter with these dispatch and validation rules:

- The final effective scheme is `https`.
- The final effective hostname is exactly `www.themealdb.com`.
- The final effective path is exactly `/api/json/v1/1/lookup.php`.
- The query contains exactly one `i` value. The value is one positive decimal
  integer with no sign, whitespace, or leading zero.
- No other query parameter or fragment is present.
- The returned `idMeal` must equal the requested `i` value.
- Dispatch continues to use the final effective URL after an ordinary redirect.

Parse the JSON document already returned by `_fetch_document`. Do not add an
HTML parser, browser, JavaScript fallback, website scrape, search fallback, or
second HTTP request. The parser must:

1. require one top-level `meals` property containing exactly one object;
2. require nonempty string values for `idMeal`, `strMeal`, and
   `strInstructions`;
3. pair `strIngredient1` through `strIngredient20` with the same-numbered
   `strMeasure` field, in numeric order;
4. trim surrounding whitespace, ignore a null or empty Ingredient slot, reject
   a nonempty measure whose Ingredient slot is null or empty, and keep an
   Ingredient with an empty measure;
5. emit each Ingredient line as `"{measure} {ingredient}"` when the measure is
   nonempty and as the Ingredient alone otherwise;
6. reject a result with no Ingredient line instead of returning partial data;
7. keep the complete trimmed `strInstructions` value as one instruction item;
   do not split, summarize, translate, or rewrite source instructions;
8. set `declared_yield` and `serving_count` to `None`; TheMealDB lookup records
   do not provide a structured mass, volume, or serving-count field, so the
   Adapter must not infer either value from prose; and
9. use the final effective API URL as `source_url`.

Reject malformed JSON, a missing or extra result, a non-object result, missing
required fields, wrong field types, a mismatched Meal ID, invalid slot pairs,
or an empty Ingredient list with contextual `RecipeStructureError` for Adapter
`themealdb`. Return no partial `ScrapedRecipe`.

Add a synthetic JSON fixture under `data/tests/fixtures/themealdb/`. It must
model the documented response shape but must not copy a real TheMealDB recipe,
artwork URL, source prose, or API response. Add one integration test module that
replaces only `urlopen`, exercises public `scrape_recipe`, and checks final-URL
dispatch and extraction through the registered Adapter. A live API request must
not be a CI gate.

Document the Adapter under `data/docs/recipe-adapters/`. Record the exact API
and URL scope, the single-selection rule, field mapping, unsupported response
shapes, no-scrape rule, and no-search decision. Record that the development key
is for development and educational use, published applications need the
applicable paid access, the API must not be resold, TheMealDB must be credited
when its data or artwork is published, and source copyright or trademark
notices must not be removed. Link the current official API documentation and
terms. State that this Adapter does not retain artwork or establish production
approval.

## Acceptance Criteria

- `scrape_recipe` accepts a synthetic final URL in the exact approved lookup
  shape and returns that final URL, the Meal title, ordered measure-and-
  Ingredient lines, the complete instruction string as one item,
  `declared_yield=None`, and `serving_count=None`.
- Redirect dispatch uses the final URL. Non-HTTPS, bare-domain, unrelated-host,
  hostname-suffix, website Meal page, other API-version or key, non-lookup,
  missing-ID, duplicate-ID, extra-query, fragment, signed, zero, leading-zero,
  and nonnumeric-ID URLs fail without a successful `themealdb` result.
- Null and empty Ingredient slots are ignored. An Ingredient with an empty
  measure is retained. A nonempty orphan measure, empty Ingredient list,
  malformed JSON, null or empty `meals`, multiple Meals, wrong result types,
  missing required fields, blank title or instructions, and mismatched
  `idMeal` fail with contextual `RecipeStructureError` for `themealdb` after
  that Adapter matches.
- The synthetic fixture and tests contain no copied recipe, artwork, or live API
  payload. Tests assert observable values and failure fields, not helper
  implementation.
- Existing recipe Adapters and shared fetch and error contracts remain
  unchanged. No search, list, filter, random, Premium, artwork, source-following,
  bulk acquisition, new CLI command, production record, or live-network test is
  added.
- The Adapter documentation records the official-access, attribution, and
  production-use limits without claiming that technical access grants
  production approval.
- Run `cd data && uv run python -m unittest tests.test_recipe_scrape_integration
  tests.test_themealdb_recipe_adapter_integration` and get exit status 0.
- Run `cd data && uv run pyright src tests` and get exit status 0.
- Run `cd data && uv run ruff check src tests` and get exit status 0.
- Run `scripts/check_data_boundary.py` from the repository root and get exit
  status 0.
