# Task 2

## Description

portfolio. This task implements
[ARCH-013](../../architecture/architecture.md#arch-013--food-catalog-data),
depends on [Task 1](1.md), and must use the registered `wikibooks` Adapter
through `scrape_recipe`. Do not add a second acquisition path, crawl a category,
or use a live-page test as a CI gate.

The requested “Pattaya fried tice” item means the source article named
“Pattaya Fried Rice.” Use reviewed Polish names for all Meal records. Keep the
English names in the table as the canonical English catalog names.

Acquire and review one article at a time. Use each final effective article URL
as the Meal `source`. The current Ají de Gallina article uses `Preparation` as
its level-two instruction heading instead of `Procedure`. Extend the Wikibooks
Adapter to accept exactly one of these headings for the required ordered
instruction section. Continue to reject a missing heading, both headings, or a
duplicate of either heading. Keep all other Task 1 dispatch, parsing, error,
license, and no-crawl contracts unchanged. Update the Adapter documentation and
its sanitized integration fixture coverage for this supported heading variant.

For each Meal:

1. Review every acquired Ingredient line and select one deterministic recipe
   variant where the article gives optional items, ranges, or alternatives.
2. Reuse an existing Ingredient when its reviewed identity matches. Otherwise,
   add one production Ingredient record with the next unused stable ID, a
   primary source for its macro profile, and all recipe terms that are needed
   for unambiguous resolution.
3. Convert every retained quantity to grams with the existing quantity and
   density contracts. Keep explicit `to taste` lines qualitative. Do not invent
   a quantity for an optional item that the selected variant omits.
4. If the current Meal compiler cannot record an explicit omitted optional or
   alternative line while preserving its complete line-review invariant, add
   one narrow reviewed omission decision to that compiler. The decision must
   name the exact source line and a fixed reason. It must not permit an
   unreviewed line to disappear.
5. Write short agent-authored preparation steps. Do not copy Wikibooks
   instruction prose into a Meal, fixture, test, or generated catalog.
6. Use the existing summed-input-mass yield contract and derive a Serving only
   when the Adapter returns a valid serving count.
7. Compile and write the Meal under `data/meals/` with the stable ID and an
   English slug from the table.

Append one Food Family with stable ID `3` and names `{"en": "Spaghetti",
"pl": "Spaghetti"}`. Set `food_family_id` to `3` on Meal 15 and Meal 16. The
other 14 new Meals must not use this family and must omit `food_family_id` in
this task. Do not change the existing Dumplings or Pizza families.

Add integration coverage for the completed production records. It must validate
the 16 stable IDs, exact source URLs, localized names, Ingredient references,
positive calculated yields, optional derived Servings, and deterministic
catalog export. It must also prove that Food Family 3 exists once, Meals 15 and
16 are its only members, and the exported Food Objects retain that membership.
Do not retain live Wikibooks HTML or copied recipe prose as a fixture.

Regenerate `data/catalogs/preview.json` only through the installed catalog
export command after all source records validate. Do not edit the generated
catalog by hand.

## Acceptance Criteria

- `data/meals/` contains one valid Meal for each table row, with IDs 2–17 and
  the exact corresponding source URL. No ID, source URL, or localized name is
  duplicated.
- Every new Meal compiles from one reviewed `ScrapedRecipe`; every acquired
  Ingredient line has one explicit retained, qualitative, discarded-water, or
  reviewed-omission decision.
- All referenced Ingredients are valid production records. Existing matching
  Ingredients are reused, and new Ingredient IDs and normalized recipe terms
  are unique.
- Meal steps are short agent-authored text and do not reproduce source
  instruction prose.
- The Wikibooks Adapter accepts one `Preparation` instruction section as an
  alternative to one `Procedure` section and rejects ambiguous combinations.
  Its Task 1 behavior is otherwise unchanged.
- `data/food_families.json` contains Food Family 3 once. Meals 15 and 16 both
  reference it, no other Meal references it, and both exported Food Objects
  have `foodFamilyId: 3`.
- The production-record integration coverage checks the 16 Meals as one catalog
  behavior. It does not add one tautological test per JSON field or a live-page
  CI dependency.
- Run `cd data && uv run obiad-data validate --ingredients-dir ingredients
  --meals-dir meals` and get exit status 0.
- Run `cd data && uv run python -m unittest
  tests.test_wikibooks_recipe_adapter_integration
  tests.test_wikibooks_meal_catalog_integration
  tests.test_catalog_export_integration` and get exit status 0.
- Run `cd data && uv run pyright src tests` and get exit status 0.
- Run `cd data && uv run ruff check src tests` and get exit status 0.
- Run `scripts/check_data_boundary.py` from the repository root and get exit
  status 0.
