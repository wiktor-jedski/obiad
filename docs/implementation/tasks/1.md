# Task 1

## Description

Add one `wikibooks` recipe Adapter to the offline production-data authoring
workflow in [`data/src/obiad_data/recipe.py`](../../../data/src/obiad_data/recipe.py).
The Adapter must use the existing `scrape_recipe` seam and return one
`ScrapedRecipe`. It must not create a second acquisition interface.

This task implements the recipe acquisition part of
[ARCH-013](../../architecture/architecture.md#arch-013--food-catalog-data). It
does not change the application catalog, backend, frontend, or OpenAPI
interface.

Use `https://en.wikibooks.org/wiki/Category:Recipes` as the source portfolio.
The category contains thousands of pages and includes non-Cookbook user pages.
The Adapter must therefore fetch only one explicit agent- or developer-selected
recipe URL at a time. It must not crawl the category, follow category
pagination, expose bulk acquisition, or write a Meal automatically. The current
Wikimedia robots policy disallows the `/w/` and `/api/` paths needed for Action
API category pagination. A category crawler is not part of this task.

Register the Adapter with these dispatch rules:

- The final effective hostname is exactly `en.wikibooks.org`.
- The final effective path is one `/wiki/Cookbook:<title>` article path.
- The category page, user pages, special pages, `/w/` paths, query-based article
  routes, and unrelated hosts do not match.
- Dispatch continues to use the final effective URL after an ordinary redirect.

Parse the rendered article HTML already returned by `_fetch_document`. Do not
add an Action API, REST API, browser, JavaScript, or wikitext fallback. The
parser must:

1. require one nonempty article title;
2. require the rendered category list to contain `Category:Recipes`;
3. reject a page marked as an incomplete recipe or a Cookbook disambiguation
   page;
4. require one `Ingredients` level-two section and collect each visible list
   item in document order, including items grouped under level-three headings;
5. require one `Procedure` level-two section and collect each visible ordered
   step in document order, including steps grouped under level-three headings;
6. reject missing, duplicate, empty, table-only, nested-list, or ambiguous
   required structures instead of returning partial data;
7. map a single positive finite `Servings` summary value or range through the
   existing `parse_serving_count` contract and use `None` when the summary has
   no `Servings` row;
8. set `declared_yield` to `None`; a Wikibooks `Yield` label can use unsupported
   concepts such as pots, bowls, or pieces, so this Adapter must not guess a
   mass or volume; and
9. use the final effective article URL as `source_url`.

Convert rendered links and inline formatting to their visible text. Decode HTML
entities and keep meaningful Unicode quantity characters. Preserve Ingredient
and Procedure item order. Exclude edit controls, references, category text,
notes, warnings, equipment, and navigation. Do not copy source instructions to
Meal files: the existing Meal compiler still requires short agent-authored
steps, reviewed Ingredient resolution, quantity conversions, names, identity,
yield, and Food Family decisions.

Add a sanitized synthetic HTML fixture under
`data/tests/fixtures/wikibooks/`. It can model the observed Wikibooks structure,
but it must not copy recipe prose or ingredient lines. Add one integration test
module that replaces only `urlopen`, exercises public `scrape_recipe`, and
checks final-URL dispatch and extraction through the registered Adapter.

Document the Adapter under `data/docs/recipe-adapters/`. Record the exact URL
scope, single-selection rule, extraction contract, Wikimedia access policy,
CC BY-SA 4.0 attribution obligation, no-crawl decision, unsupported HTML
shapes, and the rule that only the final article URL enters a Meal as its
source. Do not claim that technical access grants production approval.

## Acceptance Criteria

- `scrape_recipe` accepts a synthetic final URL in the exact
  `https://en.wikibooks.org/wiki/Cookbook:<title>` shape and returns the final
  URL, visible title, ordered Ingredient lines, ordered Procedure steps,
  `declared_yield=None`, and the parsed optional serving count.
- Redirect dispatch uses the final URL. Category, User, Special, `/w/`, nested,
  unrelated-host, and hostname-suffix URLs fail with
  `RecipeStructureError(code="missing_expected_structure")` and no Adapter name
  when no Adapter matches.
- A matching article with no `Category:Recipes`, an incomplete or disambiguation
  marker, duplicate or missing required sections, empty items, nested lists,
  table-only Ingredients, ambiguous summary servings, or malformed serving
  values fails with contextual `RecipeStructureError` for Adapter
  `wikibooks`. No partial `ScrapedRecipe` is returned.
- Synthetic coverage includes subsection-grouped Ingredients and Procedure
  steps, inline links and entities, a serving range, no serving row, excluded
  non-recipe sections, and all listed rejection paths. Tests assert observable
  values and failure fields, not helper implementation.
- Existing recipe Adapters and the shared fetch and error contracts remain
  unchanged. No category crawler, new CLI command, production Meal, Ingredient,
  catalog, network fixture, or live-page test is added.
- The Adapter documentation names the source and license obligations and states
  why automated category enumeration is outside scope.
- Run `cd data && uv run python -m unittest tests.test_recipe_scrape_integration tests.test_wikibooks_recipe_adapter_integration` and get exit status 0.
- Run `cd data && uv run pyright src tests` and get exit status 0.
- Run `cd data && uv run ruff check src tests` and get exit status 0.
- Run `scripts/check_data_boundary.py` from the repository root and get exit
  status 0.
